## 四、阶段 3 · 测试与质量门禁深挖

### 4.1 正面：门禁真实、可执行、无消音

- 全仓无 `continue-on-error` / `|| true` / `set +e`；`allow_failure: true` 只出现在
  `when: manual` 的任务上（等价于 GitHub 侧被跳过的 `desktop-build`）。
- `if: always()` / `if: failure()` 只用于产物上传与清理，**从不用于门禁**。
- `golangci-lint-action` 的 `only-new-issues` 默认为 false → GitHub 的 lint 门禁是**全仓**，
  与 GitLab 侧 `golangci-lint run` 一致。
- 覆盖率门禁检查 profile 中 `count==0` 的语句块，而非 1 位小数的百分比——避免了 99.96% 被
  四舍五入成 100.0% 而漏过回退。

### 4.2 但覆盖率的「形状」掩盖了缺陷

- **本轮 P0 中有 4 个在 100% 语句覆盖下存活**。语句覆盖率对本项目的缺陷类型
  （分支语义、数据形状、跨源字段映射）**不敏感**。
- 21 个前端测试名**硬编码源码行号**（如 `api.test.ts:1251,1265,1286`），且行号**已经过期**
  （实际 `??` 在 `api/storage.ts:49`/`:196`，非数组回退在 `:185`）——测试在描述一个不存在的版本，
  属实现耦合而非行为断言。
- `i18n/coverage.test.ts:69-81` 把**注释里的**键形字符串也算"已使用"；`:140-143` 只比对**键数量**
  做双语对称 → 盲区存在（当前实测 0 死键、670/670 对称，暂未造成漏检）。
- 全部 `/api/**` 被 `page.route` mock（`features.spec.ts:322`）→ **不存在"真实 Go 后端 + 真实前端
  产物"的联调门禁**；前后端 DTO 契约只靠单测与契约测试保障。

### 4.3 契约门禁的实际断言范围（根因分析）

本节记录审查时点的门禁断言范围。审查点名的两处缺口——**响应契约门禁缺失**与**请求体字段
门禁只覆盖硬编码端点族**——已于 2026-09-19 当轮补齐（证据见 [`features.md`](features.md) §S）：

| 门禁 | 审查时实际只断言 | 现状态 |
|---|---|---|
| `api_doc_test.go` `TestAPIDocDocumentsRequestBodyFields` | **单向** `OpenAPI ⊆ docs` + `strings.Contains` 子串匹配 | ✅ 改为机械抽取文档请求体顶层键后**双向**比对，去掉子串匹配 |
| `openapi_contract_test.go` `...RequestBodyMatchesHandlers` | **硬编码 7 个端点族** | ✅ 新增 `openapi_request_fields_test.go` 全量遍历「注册表字段集 ⇔ handler 解码结构体字段集」（保留原逐条断言作为针对性回归） |
| `openapi_inputsource_test.go` | 只比对"有无 `readJSON(`" | 维持（字段名交全量遍历门禁） |
| `api_doc_test.go` `TestAPIDocMatchesRoutes` | 路由集合双向 diff；解析正则只匹配**行首** `METHOD /api` | 维持（行内 / 缩进写法仍不解析） |
| `deadcode_gate_test.go` | 仅 `^_ = ident` 与 `^var _ = expr` | 维持（其余交 golangci-lint `unused`） |

**新增的响应契约门禁**：`openapi_response_contract_test.go` 对 `components.schemas` 的每个共享
schema 机械抽取对应 Go DTO 的 `json` tag，做双向比对（schema 多写 = 幻影字段，漏写 = 客户端丢字段）。
它上线即修正了 `Account` 的幻影字段与漏记 `useSSL`。

> **残留范围（须人工跟踪）**：响应门禁只覆盖 `components.schemas` 的**共享** schema；各端点内联
> 或 `map[string]any` 手工拼装的响应仍无机械门禁。全量请求体门禁对注册表自由体（`openapi.Obj()`）
> 跳过字段集比对。这些「断言范围」已写进两个门禁文件的头部注释，避免下轮把"有门禁"误读为"已全量收敛"。
