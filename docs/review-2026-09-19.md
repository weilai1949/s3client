## 四、阶段 3 · 测试与质量门禁深挖

### 4.1 正面：门禁真实、可执行、无消音

- 全仓无 `continue-on-error` / `|| true` / `set +e`；`allow_failure: true` 只出现在
  `when: manual` 的任务上（等价于 GitHub 侧被跳过的 `desktop-build`）。
- `if: always()` / `if: failure()` 只用于产物上传与清理，**从不用于门禁**。
- `golangci-lint-action` 的 `only-new-issues` 默认为 false → GitHub 的 lint 门禁是**全仓**，
  与 GitLab 侧 `golangci-lint run` 一致。
- 覆盖率门禁检查 profile 中 `count==0` 的语句块，而非 1 位小数的百分比——避免了 99.96% 被
  四舍五入成 100.0% 而漏过回退。

### 4.2 但覆盖率的「形状」掩盖了缺陷

> **本节已清零**。原有的四条盲区已全部闭环并落为回归门禁（见 [`features.md`](features.md)
> §U / §V / §W）：
>
> - 21 个前端测试名硬编码**已过期**的源码行号（测试在描述一个不存在的版本）→ 全部改为描述行为，
>   行号留在注释，并加机械门禁（测试名不得含源码行号）。
> - `i18n/coverage.test.ts` 把**注释里的**键形字符串也算「已使用」、双语只比对**键数量** →
>   改为先剥注释再匹配 + **集合级**双向比对，两条均经变异验证。
> - 全部 `/api/**` 被 `page.route` mock、无前后端联调门禁 → 新增 `apps/web/e2e-real/`
>   （不 mock `/api`，覆盖真实浏览器直传）+ `make e2e-real` + 两套 CI 接入。

> **保留的方法论结论**：语句覆盖率对本项目的缺陷类型（分支语义、数据形状、跨源字段映射）
> **不敏感**——本轮多个缺陷在 100% 覆盖下存活。故修复一律「补门禁」而非只补缺陷。
