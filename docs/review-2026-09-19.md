## 四、阶段 3 · 测试与质量门禁深挖

### 4.1 正面：门禁真实、可执行、无消音

- 全仓无 `continue-on-error` / `|| true` / `set +e`；`allow_failure: true` 只出现在
  `when: manual` 的任务上（等价于 GitHub 侧被跳过的 `desktop-build`）。
- `if: always()` / `if: failure()` 只用于产物上传与清理，**从不用于门禁**。
- `golangci-lint-action` 的 `only-new-issues` 默认为 false → GitHub 的 lint 门禁是**全仓**，
  与 GitLab 侧 `golangci-lint run` 一致。
- 覆盖率门禁检查 profile 中 `count==0` 的语句块，而非 1 位小数的百分比——避免了 99.96% 被
  四舍五入成 100.0% 而漏过回退。

### 4.2 但覆盖率的「形状」掩盖了缺陷

- **本轮 P0 中有 4 个在 100% 语句覆盖下存活**。语句覆盖率对本项目的缺陷类型
  （分支语义、数据形状、跨源字段映射）**不敏感**。
- 21 个前端测试名**硬编码源码行号**（如 `api.test.ts:1251,1265,1286`），且行号**已经过期**
  （实际 `??` 在 `api/storage.ts:49`/`:196`，非数组回退在 `:185`）——测试在描述一个不存在的版本，
  属实现耦合而非行为断言。
- `i18n/coverage.test.ts:69-81` 把**注释里的**键形字符串也算"已使用"；`:140-143` 只比对**键数量**
  做双语对称 → 盲区存在（当前实测 0 死键、670/670 对称，暂未造成漏检）。
- 全部 `/api/**` 被 `page.route` mock（`features.spec.ts:322`）→ **不存在"真实 Go 后端 + 真实前端
  产物"的联调门禁**；前后端 DTO 契约只靠单测与契约测试保障。
